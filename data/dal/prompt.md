==================================================

The service must support two PostgreSQL connections:
- metadata DB connection
- operational DB connection

Implement separate data access layers and configuration for them. Keep metadata access isolated from operational query execution.

The operational query engine must:
- Resolve source schema/table from metadata.
- Resolve joins from metadata.
- Resolve dimensions/measures from metadata.
- Resolve period expression based on selected frequency.
- Resolve start and end period filter snippets from metadata pattern rules.
- Build SELECT, FROM, JOIN, WHERE, GROUP BY, ORDER BY, LIMIT, OFFSET safely.
- Prevent unsupported dimensions, measures, filters, and sorts.
- Prevent arbitrary SQL clauses from clients.

Prefer a query builder strategy with a strict internal DSL rather than ad hoc string assembly. If you must assemble SQL text, do it through a constrained compiler that only emits prevalidated fragments from metadata and parameter placeholders for values.
