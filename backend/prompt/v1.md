Build ONLY the API Layer service for my chatbot system.

Important rules:
- Do NOT modify the Main Chatbot Service.
- Do NOT modify any specialized service.
- Do NOT create code for Q&A Service.

Architecture:

Frontend
  → API Layer
  → Main Chatbot Service
  → Specialized Services
  → Main Chatbot Service
  → API Layer
  → Frontend

Authoritative system flows:

Normal chatbot text:
  Main Chatbot Service token stream
  → API Layer SSE proxy
  → Frontend fetch streaming

Long-running tasks:
  Main Chatbot Service
  → RabbitMQ
  → Worker
  → MinIO/S3
  → job result URL

The API Layer must not insert RabbitMQ, a worker, or object storage into the
normal chatbot text path. The frontend must receive normal text tokens directly
through the API Layer's SSE proxy.

Streaming architecture:

Frontend
  → POST /api/v1/chat/stream
  → API Layer validates auth, chat_id, project_id, rate limit
  → API Layer calls Main Chatbot Service internal stream endpoint
  → Main Chatbot Service generates live tokens
  → API Layer forwards token stream to frontend
  → Frontend renders response smoothly

Important streaming rule:
- Main Chatbot Service is the streaming source.
- API Layer is only the SSE proxy/gateway.
- API Layer must not generate chatbot answer.
- API Layer must not store full streamed content permanently.
- Frontend must not call Main Chatbot Service directly.

RabbitMQ rule:
- RabbitMQ is for long-running background jobs only.
- Normal chatbot text streaming must not use RabbitMQ.
- Long jobs include image generation, chart generation, file processing, PDF/Excel export, and large calculator reports.
- Main Chatbot Service publishes long-running jobs to RabbitMQ.
- A worker consumes each job, performs the work, uploads the artifact to MinIO/S3, and records or returns the job result URL through the Main Chatbot Service's job system.
- API Layer does not need to publish to RabbitMQ.
- API Layer only proxies job status and result requests to Main Chatbot Service.
- API Layer must not consume RabbitMQ jobs or upload generated artifacts to MinIO/S3.

Request:
{
  "email": "test@example.com",
  "password": "password123"
}

Behavior:
- Apply rate limit: 5 requests per minute per IP.
- Verify user.
- Create access token.
- Create refresh token.
- Store refresh token hash in database.
- Create audit log: user_login.
- Return access token, refresh token, and user data.

POST /api/v1/auth/refresh

Behavior:
- Validate refresh token.
- Check token hash exists and is not revoked.
- Issue new access token.
- Optionally rotate refresh token.
- Return new tokens.

POST /api/v1/auth/logout

Behavior:
- Require authentication.
- Revoke refresh token if provided.
- Blacklist current access token in Redis.
- Create audit log: user_logout.
- Return success.

GET /api/v1/auth/me

Behavior:
- Require authentication.
- Return current user.

Token rules:

Normal chat send behavior:

POST /api/v1/chat/send

Request:
{
  "chat_id": "optional-chat-uuid",
  "project_id": "optional-project-uuid",
  "message": "Calculate import tax for this product",
  "attachments": [],
  "metadata": {}
}

Behavior:
1. Require authentication.
2. Apply Redis rate limit: 30 requests per minute per user.
3. Validate message is not empty.
4. If chat_id is null:
   - Create a new chat_thread in API Layer.
   - If project_id is provided, validate project belongs to user and attach chat to project.
   - Generate title from the first 40 characters of message.
5. If chat_id is provided:
   - Validate the chat belongs to authenticated user.
   - Validate status is not deleted.
6. Forward request to Main Chatbot Service:
   POST {MAIN_CHATBOT_SERVICE_URL}/internal/chat/send

Forward payload:
{
  "chat_id": "<chat_id>",
  "project_id": "<project_id or null>",
  "user_id": "<user_id>",
  "role": "<user_role>",
  "message": "<message>",
  "attachments": [],
  "metadata": {},
  "request_id": "<request_id>"
}

7. Receive response from Main Chatbot Service.
8. Update chat_threads:
   - last_message_preview = first 120 characters of user message
   - last_activity_at = now
   - updated_at = now
9. If chat has project_id, update projects.last_activity_at = now.
10. Return response to frontend with chat_id and project_id included.

Normal response example:
{
  "chat_id": "uuid",
  "project_id": "uuid or null",
  "message_id": "message id from main service",

SSE response format:

event: start
data: {"chat_id":"uuid","project_id":"uuid or null","request_id":"uuid"}

event: token
data: {"content":"Hello"}

event: token
data: {"content":" how"}

event: token
data: {"content":" can"}

event: token
data: {"content":" I help you?"}

event: job
data: {"job_id":"uuid","job_type":"image_generation","status":"queued","progress":0,"message":"Your image is being generated"}

event: done
data: {"chat_id":"uuid","message_id":"uuid","status":"completed"}

event: error
data: {"detail":"Main Chatbot Service is temporarily unavailable"}

Streaming implementation requirements:
- Use FastAPI StreamingResponse.
- Use httpx.AsyncClient.stream to call Main Chatbot Service.
- Use media_type="text/event-stream".
- Add headers:
  Cache-Control: no-cache
  Connection: keep-alive
  X-Accel-Buffering: no
- Do not buffer the whole response.
- Forward chunks as soon as they arrive.
- Handle client disconnect safely.
- Close upstream stream when frontend disconnects.
- If Main Chatbot Service is unavailable before stream starts, return HTTP 503.
- If error happens after stream starts, return SSE error event.

Frontend streaming note for README:
- Browser EventSource supports GET only.
- Chat message needs POST.
- Frontend should use fetch streaming with response.body.getReader().
- API Layer still returns SSE-style text/event-stream.

Frontend fetch streaming example for README:

async function sendMessageStream({ token, chatId, projectId, message }) {
  const response = await fetch("http://localhost:8000/api/v1/chat/stream", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Authorization": `Bearer ${token}`
    },
    body: JSON.stringify({
      chat_id: chatId,
      project_id: projectId,
      message: message
    })
  });

  if (!response.ok || !response.body) {
    throw new Error("Streaming failed");
  }

  const reader = response.body.getReader();
  const decoder = new TextDecoder("utf-8");

  let buffer = "";
  let assistantText = "";

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });

    const events = buffer.split("\\n\\n");
    buffer = events.pop() || "";

    for (const eventText of events) {
      const lines = eventText.split("\\n");
      let eventName = "message";
      let dataText = "";

      for (const line of lines) {
        if (line.startsWith("event:")) {
          eventName = line.replace("event:", "").trim();
        }

        if (line.startsWith("data:")) {
          dataText += line.replace("data:", "").trim();
        }
      }

      if (!dataText) continue;

      const data = JSON.parse(dataText);

      if (eventName === "start") {
        console.log("Chat started:", data.chat_id);
      }

      if (eventName === "token") {
        assistantText += data.content;
        renderAssistantMessage(assistantText);
      }

      if (eventName === "job") {
        showJobCard(data);
      }

      if (eventName === "done") {
        markMessageDone(data);
      }

      if (eventName === "error") {
        showError(data.detail);
      }
    }
  }
}

Frontend smooth rendering pattern for README:

let pendingText = "";
let visibleText = "";
let isRendering = false;

function appendToken(token) {
  pendingText += token;

  if (!isRendering) {
    isRendering = true;
    requestAnimationFrame(renderLoop);
  }
}

function renderLoop() {
  if (pendingText.length > 0) {
    visibleText += pendingText;
    pendingText = "";
    renderAssistantMessage(visibleText);
    requestAnimationFrame(renderLoop);
  } else {
    isRendering = false;
  }
}
